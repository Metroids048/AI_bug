# ADR: M2.6 Real-Model Blind Research Gate

## Decision

M2.6 adds a repeatable local-only experiment around the existing research workflow. A real OpenAI-compatible model may receive only the program policy, scope, target profile/API descriptions, researcher-owned accounts, and neutral researcher-owned fixture metadata needed to form valid requests. It never receives benchmark ground truth, fixture internals, or prior findings.

Each experiment creates a fresh run context and executes the nine benchmark scenarios for three independent rounds. Planner, validator planner, skeptic, and impact reviewer outputs are persisted with provider usage and prices. Every generated action still passes `ScopeGuard`; `LocalLabExecutor` remains the only target executor and accepts only `lab://` targets.

The final decision remains deterministic: only objective control/test observations, complete redacted evidence, two reproductions, scope ALLOW, observed impact, and advisory review thresholds can produce `SUBMISSION_READY`.

## Scenario Classes

- Three true positives: vulnerable IDOR, information disclosure, and repeatable business logic.
- Three normal safe controls: ownership-checked resource, non-sensitive configuration, and state-checked reward.
- Three deceptive safe controls: public profile by arbitrary ID, intentionally shared document, and non-sensitive `internal_id`.

The benchmark fixture owns ground truth. The model-facing `TargetProfile` exposes only public descriptions and test-account rules; scenario labels and expected outcomes are excluded from provider context.

## M2.6.1 Hardening

- Model-facing paths and descriptions are neutral business descriptions; `kind`, scenario labels, security conclusions, and benchmark truth are filtered before Provider calls.
- OpenAI-compatible requests include the exact Pydantic JSON Schema. Providers may opt into `response_format=json_schema`; unsupported or invalid output receives at most one repair containing only the validation error and previous output.
- Route dispatch in the local benchmark uses exact paths so a prefix such as `/api/environment` cannot accidentally select `/api/environment/details`.

The offline `blind` provider may use an internal fixture mapping solely as a deterministic regression surrogate. It is not evidence of real-model discovery. The Real-Model Gate remains blocked until an explicitly configured endpoint completes the full independent-round benchmark.

## M2.6.2 Fixture Metadata

`TargetProfile` exposes structured `test_resources` (`doc-a`, `item-a`, `record-a`, `item-1`) and `test_inputs` (`WELCOME`) alongside the two researcher-owned test accounts. These fields describe how to form valid requests only; they do not include expected status, vulnerability labels, security conclusions, or benchmark truth. The local fixture uses `record-a` rather than the semantically suggestive `shared-doc` value.

## Measurement

`ExperimentRun` and `ExperimentCaseResult` records aggregate TP, FP, FN, precision, recall, scope violations, reproduction/evidence gate failures, token usage, known/unknown cost, and cost per true candidate. Missing usage or prices remain UNKNOWN and cannot be treated as zero.

## Non-goals

No live HackerOne/Bugcrowd/Intigriti target, recon, scanner, browser automation, auto-submit, scheduler, queue, dashboard, or multi-program execution is added.
