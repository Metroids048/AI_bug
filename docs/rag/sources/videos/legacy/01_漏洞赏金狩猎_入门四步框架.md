# 漏洞赏金狩猎：入门四步框架

## 一句话理解

这条视频不是教具体漏洞，而是告诉新手：**不要先学几年网安再开始，先进入真实 Bug Bounty 环境，在做中学，然后逐渐形成自己的方法。**

作者把成长过程压缩成四步：

```text
Get Going
→ Get Good
→ Get Smart
→ Stand Out
```

白话就是：

```text
先开始
→ 先练会
→ 再提高效率
→ 最后形成自己的优势
```

---

# 第一步：先开始，不要过度准备

最先做的不是研究所有漏洞类型，而是：

1. 在 HackerOne、Bugcrowd、Intigriti 等平台创建账户；
2. 选 2～3 个项目；
3. 阅读项目 Scope；
4. 进入真实目标，开始观察功能；
5. 遇到不懂的漏洞类型，再去学习。

作者反复强调：很多新手卡在“我还没准备好”。

正确顺序更像：

```text
看到功能
↓
不知道这里可能有什么问题
↓
查这种功能常见漏洞
↓
做实验
↓
回到真实目标验证
```

而不是：

```text
先学完所有网安知识
↓
几年后再开始
```

---

# 第二步：先练出一套自己会用的打法

新手最容易犯的错误是：

```text
今天学 XSS
明天学 SSRF
后天学 SQLi
大后天学 RCE
```

最后什么都知道一点，但没有任何一类真正会找。

视频的建议是：

## 先选择你更适合的方式

大致分两类：

### A. 自动化 / 大范围 Recon

适合：
- Scope 很大的 Program；
- 子域很多；
- 资产变化快；
- 需要持续找新目标。

典型工具包括：
- Nuclei；
- Sublist3r / Amass；
- httpx；
- 自己写的小脚本。

目标不是“扫描器自动报漏洞”，而是：

**自动产生值得人工继续研究的线索。**

### B. 手工 / 深度应用测试

适合：
- 一个大型 Web App；
- 登录以后功能复杂；
- API 很多；
- 权限、角色、业务逻辑复杂。

典型工具：
- Burp Suite；
- 浏览器 DevTools；
- JavaScript / endpoint 分析工具。

这种方式更重视：
- 业务流程；
- 账号角色；
- 参数变化；
- 权限边界；
- 边缘情况。

# 视频举的核心例子：不要只背漏洞名，要围绕“功能”学习

比如看到一个文件上传功能，不应该只想：

> “这是上传功能。”

应该问：

```text
允许什么文件类型？
服务端真的校验了吗？
只校验扩展名还是内容？
上传后的文件会在哪里展示？
上传内容会不会被浏览器执行？
能不能绕过文件类型限制？
```

于是你会自然接触：
- XSS；
- 文件类型绕过；
- 非预期文件上传；
- 内容解析问题。

核心思想是：

**从功能出发找攻击面，而不是从漏洞字典出发乱套模板。**

---

# 第三步：开始“聪明地挖”

有了第一批经验以后，就不能一直靠手工重复。

作者建议把赚到的钱、时间和经验重新投入到工作流里。

包括：

## 1. 用更好的数据源

例如：
- Shodan；
- Censys；
- SecurityTrails。

这些服务能帮助你更快知道：
- 某公司有哪些资产；
- 哪些服务暴露在公网；
- 域名和 IP 的变化；
- 新资产出现。

## 2. 自动化重复工作

把重复动作做成：
- 脚本；
- 模板；
- 定时监控；
- 通知。

比如：

```text
发现新子域
↓
自动探活
↓
自动收集 JS
↓
自动提取 endpoint
↓
只把高价值变化提醒给你
```

## 3. 开始理解“什么 Program 适合自己”

不同 Program 的赚钱方式不同。

你应该慢慢知道：
- 自己擅长大 Scope 还是单应用；
- 擅长自动化还是业务逻辑；
- 哪类漏洞你复现快；
- 哪类目标竞争小；
- 哪些 Program 的规则、响应速度和奖金更适合你。

这一步的核心不是“工具更多”。

而是：

**更少地浪费时间。**

---

# 第四步：建立别人没有的优势

当所有人都会 Burp、Nuclei、ffuf 时，仅仅“会工具”不再是优势。

作者建议通过以下方式形成差异：

- 自己开发工具；
- 开源模板；
- 公开研究；
- 写文章；
- 做教学；
- 跟其他研究员协作；
- 建立个人品牌。

表面看是在“做社区贡献”，本质上会带来：

- 更深的理解；
- 更多同行交流；
- 更好的私有项目机会；
- 更强的工具能力；
- 更稳定的方法论。

---

# 这条视频最重要的 8 个结论

1. **先开始，再补知识。**
2. 不要同时学几十种漏洞，先形成一套能重复的打法。
3. 从“功能”理解漏洞，比背漏洞名字更重要。
4. 自动化的价值是找线索和省时间，不是盲目批量扫描。
5. 真实 Bug Bounty 的能力来自大量真实目标的积累。
6. 赚到第一笔钱以后，应该反向投资工具、数据源和自动化。
7. 最终需要形成自己的 Methodology，也就是稳定工作流。
8. 真正长期有优势的人通常有自己的工具、经验库、研究习惯或社区影响力。

# 对 AI 时代最有用的改写

把作者的四步放到现在，可以变成：

```text
先让 AI 跟着你做真实授权练习
↓
让 AI 熟悉几类高价值漏洞
↓
把重复动作做成 Agent / Skill / Tool
↓
用历史 Finding 和 Bad Case 持续反向训练 RAG
```

你本人不需要承担全部执行，但必须知道每一步为什么做、什么结果才算有效。

---

# 最少术语

- Recon：先把目标有哪些资产、页面、接口搞清楚。
- Endpoint：一个具体 API 地址。
- Scope：项目明确允许测试的范围。
- Nuclei：http 请求模板式检测工具。
- Burp Suite：抓取和修改 Web 请求的工具。
- XSS：攻击者输入的脚本被网站错误执行。
- RCE：攻击者最终能让服务器执行不该执行的命令。
